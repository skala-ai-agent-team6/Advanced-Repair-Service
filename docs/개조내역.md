# 팀원 코드 통합 개조내역 (2026-10-21)

팀원 코드를 합쳐 한 번에 돌아가게 하면서 고치거나 지운 것만 적었다. 코드에서 고친 곳에는 `[통합]` 주석이 붙어 있다.

## 통합용으로 새로 만든 것 (`integration/`)
- `auto_photo.py`: 프론트 추가 사진 화면 대역. 요청 후 `AUTO_PHOTO_GRACE`초(기본 60) 동안 아무도 안 올리면 지정 사진을 제출한다.
- `demo.py`: 접수부터 진단 결과까지 API로 시험한다 (`complete` | `photo`).
- 시연 사진은 레포 맨 위 `source/` 3장 (01 PCB, 32 기계·사진요청용, 09 추가 사진). 대역·demo도 이 사진을 쓴다.

## 임시로 넣은 것 (나중에 빼거나 바꿀 것)
- 기계 MCP 찌그러짐 모델은 자동차 외판 모델이다. 출력 이름만 `dent/breakage`로 바꾸고 원래 이름은 `raw_label`로 보낸다. 오탐이 많다.
- 강판 결함 모델도 거의 모든 사진에서 무언가를 검출한다.
- `DEMO_FORCE_PHOTO`, `auto_photo.py`는 시연용이다.
- 기존 이 레포의 `docker-compose.yml`(Kafka만)은 지웠다. `backend/compose.yaml`이 Postgres+Kafka를 같은 포트로 띄운다.
- 문서 md(팀원 docs, HARNESS_STEP, INTEGRATION_STATUS 등)는 지웠다. 원본 레포에 그대로 있다.

## 남은 것
- 처리 이력이 비어 있다 (백엔드 상세 응답에 이벤트가 없다).
- 추천 부품이 모델 호환으로 걸러지지 않는다.
- 에러코드 해석은 출처(에러코드표)가 없어 빈 배열이다.
- 유사 사례는 외부 공개 데이터라 청소기와 거리가 있다.
- business-mcp는 붙이지 않았다. Spring dev는 가짜 MCP를 쓴다.
- 위 수정은 각 담당자 확인이 필요하다.
